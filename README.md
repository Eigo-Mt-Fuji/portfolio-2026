## 生成AIの仕事・学習への利用

1. 新しく学んだことを整理
  - インプットは、仕事の時と読書の時で分けて考える
    - PDF読書時: Skimノートに以下の記録をつけてエクスポートする(2025年からのルール)
      - [TIPS]: 新しい情報・TIPS
      - [Q] :わからないこと。疑問・質問
      - [EXP]: やってみたいこと
    - 仕事の時: claudeプロンプトのセッションをもとにサマリーを作成させる
  - 上記を入力として、AIエージェントに、以下の質問をさせる
    - 新しく学んだことを整理したいです。次の3つに分類してください。
      - ①自分が理解すべき
      - ②AIへ任せれば十分
      - ③まだ判断できない

2. 今日の仕事をAI Context Playbookとして整理
  - claudeプロンプトのセッションをもとにサマリーを作成させる
  - 上記を入力として、AIエージェントに、以下の質問をさせる
    - 今日の仕事をAI Context Playbookとして整理したいです。以下の順で質問してください)
      - 1. 今日最初に持っていた情報は？
      - 2. 今日追加された重要な情報は？
      - 3. 追加情報でAIの回答はどう変わった？
      - 4. AIが最後まで苦手だったことは？
      - 5. 人が最終判断したことは？
      - 6. 次回この案件なら最初から何をAIへ渡す？

### エージェントスキル・サブエージェント・ループエンジニアリングの低負担・日常運用のための基礎確認

```
エージェントスキルの形式
    https://agentskills.io/specification
    - Directory structure
    - SKILL.mdフォーマット

エージェントスキルとは？
    AIエージェントに専門的な作業手順や知識を教え込むための、指示書とリソースをまとめたフォルダ形式の仕組み
    役割は、手順書、マニュアル、レシピなどに該当する
    通常は、繰り返し行われる手続きがスキル化され、同じ入力に対して同じ出力が期待される

サブエージェントとの違い
    サブエージェント（Sub-agents）は 独立したコンテキストで作業をこなす専門スタッフ（実行者）
    独立したコンテキストウィンドウを持ち、並行・単独で作業し、親エージェントに連携する
    同じ入力に対して、観点や目的に応じて異なる出力が期待される場合がある

Claudeの定義済みスキルとは。スキルとはどんな実装になるのか
    https://github.com/anthropics/skills/tree/main
    https://code.claude.com/docs/en/skills

ループエンジニアリングの要素 https://qiita.com/nogataka/items/bad6d9e769d9a0e41c19
    トリガー いつ依頼するか
        「あなたが頼んだとき」「毎週金曜の朝」のような時刻
        「PRにラベルが付いたら」のようなイベントが該当
    アクション　何を依頼するか
        「レビューする」「自動テストを足す」「テストを実行する」「修正する」など
        1回のループで1つの作業に絞ると、結果を確かめやすくなります
    証明　できたと判断する基準
        作業がうまくいったと、どうやって判別するか（英語では proof や verify）
        「良くなった」では、ループは止まりどきを判断できません
        「テストが全部通った」
        「目標の速度を満たした」
        機械でも測れる形にする
    メモリ　やり取りの記録
        保存する場所
         ファイル
         コミット履歴など
         ボード
    停止条件　いつ終わるか
        「成功したら止まる」
        「これ以上よくならなければ止まる」
        「3回失敗したら人に知らせる」

ループにすべきでないとき・つまずきポイント
    1回で終わる作業: やり直しが要らないなら、ループはむだな手間です。
    ゴールが決まっていない探索: 「何かいい感じにして」は成功条件が無く、止まれません。
    成功を自動で確かめにくい作業: 確認が「自分の目だけ」なら完全な自動化には早く、まずは人間のレビューを品質ゲートに組み込むのが安全です。

やってはいけない3つ（と、その防ぎ方）
    成功条件を決めずに回す → 「テストが通る」など、機械で測れる条件を先に決める。
    停止条件を付けずに回す → 「○回失敗したら人へ」など、止めどきを必ず付ける。
    学びをファイルに残さない → 進捗や結果をファイルに書き、次回そこから始める。
```
